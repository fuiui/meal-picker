# 第三部分：推荐页 HTML 骨架

## 如何查看

直接打开项目根目录的 `pick.html`。目前没有外部样式、脚本或网络请求，双击即可查看。后续引入公共导航加载等功能时再使用 VS Code Live Server。

本部分有意使用浏览器默认样式，先看清结构。颜色、卡片排版和手机布局在第六部分完善，不把当前外观当成最终设计。

## 实际完成

- 页面语言、编码、手机 viewport、独立标题和描述。
- header、nav、main、footer 四个区域；一个 h1 和有层级的 h2。
- 跳过导航的链接，导航当前页标记。
- 表单包含预算和口味选择框，默认均为不限。
- 预算包含不限、15 元以内、25 元以内；口味包含不限、不辣、辣。
- 每个选择框配套 label，使用键盘可选择。
- 推荐按钮保留位置但禁用；没有接入数据或随机功能。
- 结果区有初始说明和 aria-live，为下一部分更新内容做准备。
- 解释示例价格、未来随机可能重复、不提供下单。

Home、Meal Collection、About 尚未制作，所以导航显示文字“coming soon”，不创建死链接。第五部分完成后改成实际链接。这些临时提示在正式交付前需要移除。

## 代码怎么解释

| 代码 | 用普通话解释 |
| --- | --- |
| `<!DOCTYPE html>` | 告诉浏览器按现代 HTML 模式解析。 |
| `<html lang="en">` | 页面正文是英文，帮助辅助阅读工具选择语言。 |
| `<head>` | 存放标题、编码等页面信息，不是可见页头。 |
| `<header>` | 页面可见的顶部介绍。 |
| `<nav>` | 主要页面导航；本阶段只有推荐页可访问。 |
| `<main>` | 页面核心内容，只有一个。 |
| `<form>` | 把用户选择组织成表单，目前不发送数据。 |
| `<fieldset>` / `<legend>` | 将预算和口味归为同一组，并给组命名。 |
| `<label for="budget">` | 对应 `id="budget"`，不是装饰文字；点击能聚焦控件。 |
| `<select>` / `<option>` | 下拉选择框和每一个选项。 |
| `value="15"` | 留给 JavaScript 读取的值；读取时是字符串，第四部分再转数字。 |
| `disabled` | 本阶段按钮不可操作，避免暗示推荐功能已经完成。 |
| `aria-current="page"` | 标明导航中的当前页。 |
| `aria-live="polite"` | 将来更新结果时，让辅助阅读工具适时通知用户。 |
| `id` | 本页唯一名称，用于标签关联、跳转和后续脚本查找。 |

## 验证与边界

本部分检查 HTML 区域、标题层级、标签关联、选项、默认值、键盘操作、按钮禁用、站内链接、电脑与手机窄屏的默认布局。结果保存在 `stage-03-check.json`。

这些检查不等于正式 W3C 全量校验，也不证明随机功能已完成。没有食物数据、筛选、随机数或自动结果更新，这些属于第四部分。没有上线或远程上传。
