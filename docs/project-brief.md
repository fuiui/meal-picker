# What to Eat

## Project idea

A simple meal picker helping students choose what to eat by budget and taste.

## Audience and purpose

This website is for students who find it difficult to decide what to eat for lunch. They may have a limited budget or prefer a particular taste. The website will help them choose from a small collection of sample meals.

## Four pages

1. **Home** — Introduces the website and explains the three steps: choose a budget, choose a taste, and get a suggestion.
2. **Pick a Meal** — Lets the user select a budget and taste, then shows a randomly selected matching meal.
3. **Meal Collection** — Shows all twelve sample meals with illustrations, descriptions, example prices, and taste labels.
4. **About** — Explains the audience, selection method, content sources, AI assistance, and limitations.

## Most important page

Pick a Meal is the most important page because it provides the main function. I plan to build and test it before completing the other pages.

## Smallest useful version

The first version will have four connected pages and twelve sample meals. Users can choose any budget, up to 15 yuan, or up to 25 yuan. They can choose any taste, non-spicy, or spicy. The site filters the meals first and then selects one matching meal at random.

If no meal matches, it will ask the user to change the filters. Random choices may repeat. Refreshing the page resets the choices. Prices are illustrative examples, not current restaurant prices.

## Design and technology

The planned design uses a cream background, dark green text, and an orange-red accent. Desktop pages can use multiple columns; mobile pages will stack content vertically. The site will use HTML, CSS, and plain JavaScript, without accounts, a database, ordering, or external APIs.

## Why this project

It addresses a simple everyday decision and provides an interaction that is easy to demonstrate. The main logic is also small enough to explain: read the choices, filter the meals, select a random item, and update the page.

## Current status

This document is a planning deliverable, not evidence of an implemented website. The four pages and interaction have not been built. Codex assisted with this draft; the student should review and understand it before using it. No Git commit, upload, or course-platform submission has been made.
