# 第四部分：让网站真的推荐一道饭

## 查看与演示

双击根目录的 `pick.html` 即可使用，无需安装框架或连接服务器。确保 `meals.js` 和 `pick.js` 与 HTML 放在同一目录。当前没有外部接口或网络依赖。

1. 默认不限预算、口味，点击 Pick a meal：从 12 道食物中推荐一道。
2. 选择 Up to ¥15 和 Non-spicy：会有 3 道候选，推荐价格不超过 15。
3. 将口味改成 Spicy：旧结果被清除，提示没有符合条件的食物。
4. 把预算提高到 ¥25：只有 Mapo tofu rice 符合，连续点击也会推荐它。
5. 改回不限条件，再推荐。刷新页面后选择和结果恢复默认。

所有价格是虚构的教学示例，不是当前餐厅报价。标签是示例菜品分类。随机结果允许重复，只有一个候选时也允许重复。

## 文件职责

- `meals.js`：12 道食物的数据，字段为 id、name、price、taste、description。
- `pick.js`：读取选择、筛选、随机抽取和更新结果。
- `pick.html`：表单和结果区域，先加载数据脚本再加载逻辑脚本。

## 最重要的代码解释

```javascript
const withinBudget = budget === 'any' || meal.price <= Number(budget);
const matchesTaste = taste === 'any' || meal.taste === taste;
return withinBudget && matchesTaste;
```

`filter()` 会逐个检查食物，返回满足条件的新数组，不修改原来的菜单。`||` 表示“或者”：不限预算，或者价格不超过上限。`&&` 表示两个条件必须同时满足。选择框读出的是字符串，因此用 `Number()` 转换预算。`<=` 保证价格刚好等于预算也能留下。

```javascript
const index = Math.floor(Math.random() * candidates.length);
const meal = candidates[index];
```

`Math.random()` 产生大于等于 0、小于 1 的数。若有 3 道候选，乘 3 后范围为 0 到不足 3，向下取整只能得到 0、1、2，正好是数组下标。先筛选再随机，不会选中超预算或口味不符的食物。

如果 `candidates.length === 0`，先显示提示再 `return`，不执行随机抽取，避免读取不存在的食物。

表单监听 `submit`，调用 `event.preventDefault()` 阻止浏览器刷新和跳转；鼠标点击或键盘提交都走同一流程。修改筛选项触发 `change`，重新显示候选数量并清除旧结果。

`createElement()` 创建结果元素，`textContent` 填入纯文字，`replaceChildren()` 替换原结果而不是不断叠加。按钮初始化前保持禁用；没有 JavaScript 时显示说明。

## 老师可能会问什么

| 问题 | 回答要点 |
| --- | --- |
| 数据从哪里来？ | 本地 JavaScript 数组，价格和描述是项目示例，不是实时接口。 |
| 为什么不用数据库？ | 菜单很小且固定，不需登录或保存记录，浏览器可以独立完成。 |
| 如何保证没有超过预算？ | 先按 `<=` 筛选，再从候选数组中抽取。 |
| 为什么连续两次会相同？ | 每次独立随机，没有排除上次结果，符合第一版规则。 |
| 为什么改条件会清空推荐？ | 防止旧推荐不符合新条件而造成误解。 |
| 刷新后为什么没有保存？ | 只使用当前页面内存，没有 localStorage 或数据库。 |
| 可不可以保证每次不同？ | 可以增加记录上次结果的逻辑，但第一版没有实现；一个候选时无法不同。 |
